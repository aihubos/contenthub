# Content Hub

내 콘텐츠와 최신 관심 흐름을 연결하는 개인 콘텐츠 기획 라이브러리.

- 사이트: https://content.ai-hub-os.com/
- React · TypeScript · Vite / GitHub Pages
- 쇼츠 10개·유튜브 5개·블로그 5개, TOP 3, 날짜별 아카이브, 검색·분류
- 기획안 복사, 즐겨찾기·제작 상태는 현재 브라우저에 저장
- 트렌드 대시보드: `/?view=trends` · 플랫폼별 원문 기준일과 출처 표시
- 자동 갱신 예약은 사용자 별도 설정

## 로컬 실행

```sh
npm ci
npm run dev
npm run check
```

개발 서버의 `/` 경로를 엽니다. 상세 링크는 `?date=YYYY-MM-DD&idea=주제식별자`를 사용합니다.

## 추천 데이터 갱신 절차

1. `npm run collect`로 공개 피드를 수집합니다. 영상·글은 누적 보관하며, 피드에서 사라진 과거 자료를 자동 삭제하지 않습니다. 양쪽 수집이 모두 성공해야 파일을 바꿉니다.
2. Codex가 최신 원문을 조사하고 `work/candidate.json`에 기획안을 작성합니다. 형식은 기존 회차와 `src/types.ts`를 따릅니다. `npm run collect` 자체는 추천을 생성하지 않습니다.
3. `node scripts/install-brief.mjs work/candidate.json`으로 형식·출처·중복·5/5/5 구성을 확인한 뒤 승격합니다. 실패한 후보는 공개 인덱스에 반영하지 않습니다.
4. `node scripts/publish.mjs`는 데이터만 검사·커밋·푸시합니다. 다른 변경이 있으면 보존하고 중단합니다. GitHub Actions가 검사·빌드 후 Pages를 배포합니다.
5. GitHub 배포 성공과 공개 `data/index.json`, 해당 회차 및 실제 화면을 확인해야 갱신 성공입니다. 푸시만으로 성공 처리하지 않습니다.

## 조사 기준

- 한국어 시청자, 조회수·구독자 성장을 목표로 합니다. 쇼츠는 과학·자연·우주, 긴 영상은 원리 설명·AI 실습, 블로그는 AI 경험담 중심입니다.
- 최근 7일의 관련 공개 영상·블로그·공식 발표와 최근 30일 검색 추이를 조사합니다. 검색 결과의 수집일을 원문 발행일로 바꾸지 않습니다.
- Google Trends는 Google 검색 관심, 네이버 데이터랩은 네이버 통합검색 상대지수입니다. 유튜브 조회수·블로그 조회수·절대 검색량과 구분합니다. 네이버 일별 데이터의 반영 시차도 기준일에 반영합니다.
- 실제 원문·초록에서 확인한 범위만 적고, 접근 제한과 확인하지 못한 지표는 `coverage`와 출처 설명에 표시합니다. 부족한 근거를 숫자로 꾸며 채우지 않습니다.
- 현재 게시물 및 이전 회차와 주제를 비교합니다. 기계적 제목 검사는 보조이며, 같은 소재·주장인지는 Codex가 읽고 판단합니다. 후속편이면 연결할 기존 게시물 ID와 새 관점을 기록합니다.
- `publishedAt`은 확인하지 못하면 `null`, `checkedAt`은 실제 확인 시각입니다. `generatedAt`은 추천 작성 시각입니다. 화면의 마지막 성공 시각은 공개된 최신 회차의 작성 시각이며, 배포가 실패하면 이전 공개 시각이 유지됩니다.
- 예시 실험·후기·방문 결과를 실제 경험처럼 작성하지 않습니다. 직접 실행 후 결과를 채울 기획임을 명시합니다.

## 데이터와 장애 처리

공개 파일은 `public/data/index.json`, `published.json`, `briefs/YYYY-MM-DD.json`입니다. 새로운 회차를 추가해도 과거 자료는 유지됩니다. 같은 날짜를 다시 갱신하면 기존 원본 파일은 그대로 두고 `briefs/YYYY-MM-DD/<회차-ID>.json`에 새 회차를 추가합니다. `index.json`은 현재 회차와 원본 회차를 함께 기록합니다. 기존 `?date=YYYY-MM-DD&idea=...` 링크와 기존 `youtubeos.saved.v1` 보관함 항목은 원본 회차를 열고, 새 화면 탐색은 회차 ID를 포함해 최신 회차를 엽니다.

2026-09-10부터 추천 20개(쇼츠 10·유튜브 5·블로그 5)가 검증되지 않으면 배포하지 않습니다. 쇼츠는 우주 5개·신비한 생물 5개를 기본으로 합니다. 이월된 유튜브·블로그 기획은 원래 회차와 immutable edition을 `carriedFrom`으로 남겨 신규 조사로 보이지 않게 합니다. 수집 실패·사용량 부족·배포 실패 시 마지막 정상 사이트를 유지합니다. 브라우저는 마지막 공개 작성 시각에서 36시간이 지나면 갱신 지연을 표시합니다. 정상 운영은 조용히 진행하고 실패나 사용자 조치가 필요할 때만 알립니다.

개인 보관함은 로컬 브라우저 데이터이므로 다른 기기에 동기화되지 않으며, 브라우저 데이터를 지우면 함께 삭제됩니다.

## 검증

`npm run check`는 데이터 계약과 타입·배포 빌드를 확인합니다. 실제 브라우저에서 검색, 쇼츠 10개·유튜브 5개·블로그 5개 분류, 저장 후 새로고침, 기획안 복사, 상세 링크, 390/768/1280px 배치를 확인합니다. 검증은 현재 작업에서 직접 수행하며 멀티에이전트 리뷰를 사용하지 않습니다.

## 콘텐츠 표지

추천의 `image` 필드에 `src`, `alt`, `caption`, 선택 사항인 `sourceUrl`을 지정하면 목록과 상세에 표시합니다. 기존 회차 JSON을 보존하며 표지를 보완할 때는 `public/data/visuals.json`에 주제 ID별 이미지를 추가합니다. 원문 이미지에는 관련 원문을 연결하며, `public/assets/topics/`의 AI 생성 설명 이미지는 실제 관측 사진과 구분해 표시합니다.

## 트렌드 대시보드

`public/data/trends.json`은 수동 확인한 공식 자료의 기록입니다. Google RSS 급상승 검색량 근사치, 네이버 패션의류 쇼핑 클릭 인기검색어, YouTube 한국 주간 음악 차트를 각각 표시하며 단위를 합산하지 않습니다. 데이터 획득 위치와 범위는 `docs/trend-sources.md`를 참고하세요.

수치·출처·기준일을 확인해 JSON을 갱신하고 `npm run check` 후 배포합니다. `scripts/check-trends.mjs`는 데이터 구조와 서로 다른 날짜가 같은 그래프 축에 정렬되는지 확인합니다. 누락된 날짜의 수치를 추정하지 않고 그래프 선을 끊어 표시합니다.
